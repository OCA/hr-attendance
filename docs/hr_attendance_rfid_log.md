# HR Attendance RFID Log Module (Odoo 13 CE OCA)

## Overview

The `hr_attendance_rfid_log` module is an extension designed for Odoo 13 Community Edition (OCA standard). It significantly enhances the HR Attendance functionalities by integrating an RFID-based logging system. It captures, stores, and manages attendance events generated by RFID devices, providing an intermediary layer that ensures reliability and comprehensive tracking before the attendance is officially recorded in the core HR system.

## Needs Addressed

In many organizations, attendance tracking using hardware devices (like RFID readers) faces challenges such as network disconnections, unregistered cards, or delayed synchronizations. This module covers these needs by:

1.  **Robust Event Logging:** Instead of directly modifying the HR attendance records, the module logs all incoming RFID events into a dedicated model (`hr.attendance.rfid.log`).
2.  **State Management:** Every scan gets categorized into actionable states:
    *   **Success:** The RFID scan was successfully linked to an employee and registered as a valid check-in or check-out.
    *   **Failed:** An error occurred (e.g., the RFID card is not associated with any employee or the attendance rules were violated).
    *   **Retry:** Events that previously failed but are marked to be retried (e.g., after the card has been assigned to a user).
    *   **Ignore:** Events that administrators actively choose to dismiss, removing them from the queue of pending issues.
3.  **Traceability:** It maintains historical logs of when the event happened, the card code used, the associated IoT device, and any error messages generated during the process.
4.  **Resilience against failures:** It provides mechanisms to recover from errors (e.g., automatic or manual retry of failed events).

## User Possibilities

While using this module, an Odoo HR manager or administrator has several capabilities:

*   **Comprehensive Log Viewing:** Users can monitor all RFID scans in real-time through the list and form views provided by the module, enabling easy auditing of the attendance hardware's activity.
*   **Handle Unregistered Cards:** When an employee uses a new or unregistered RFID card, the system logs it as "Failed". The user can use a dedicated wizard directly from the log entry to **assign the unknown RFID card to an existing employee**.
*   **Automatic Retry Mechanism:** Once a card is assigned to an employee using the wizard, the related "Failed" logs are automatically set to the "Retry" state, and the system attempts to register the attendance again. There's also a cron job that can process "Retry" logs periodically.
*   **Manual Intervention:** Administrators can manually push specific logs into a "Retry" state or permanently dismiss irrelevant or duplicate scans by setting them to "Ignore".
*   **Configurable Data Purging:** To prevent database bloat, the system features a scheduled action that purges old logs based on configurable system parameters (`purge_period_success` and `purge_period_general`).

## Best Practices

When implementing and maintaining this type of hardware-integrated module, consider the following best practices:

*   **Regular Monitoring of Failed Logs:** Administrators should routinely check for failed logs to ensure employees aren't missing attendance records due to unassigned cards or hardware glitches.
*   **Data Retention Policies:** Correctly configure the `purge_period_success` (e.g., 5 days) and `purge_period_general` (e.g., 40 days) system parameters. Successful logs don't need to be kept for long since the actual attendance is recorded, while failed logs should be kept long enough to be investigated but not indefinitely.
*   **Security of RFID Cards:** Ensure that assigning an RFID card to an employee is a controlled process. The system warns if a card is already assigned, preventing accidental overrides.
*   **IoT Device Management:** Clearly identify and maintain the IoT devices pushing data to Odoo. If an device malfunctions, the logs will help pinpoint which reader is problematic.

## Proposed Improvements

To further enhance the module, the following improvements could be considered:

1.  **Automated Alerts:** Implement email or internal Odoo notifications to HR managers when the number of "Failed" logs exceeds a certain threshold within a specific timeframe, indicating a possible systemic issue.
2.  **Dashboard Integration:** Provide a visual dashboard summarizing daily successful vs. failed scans, identifying peak usage times, and showing statistics per IoT device.
3.  **Enhanced Retry Logic with Backoff:** If a retry fails due to transient database or network issues, implement an exponential backoff strategy for the cron job instead of a simple linear retry counter.
4.  **Bulk Assignment Wizard:** Enhance the wizard to allow assigning multiple unknown RFID cards to employees in a single view, perhaps matching them against expected but missing attendances.
5.  **Offline Synchronization Support:** Improve the API endpoint to better handle bulk payloads from devices that temporarily lost internet connection and are uploading cached scans.
